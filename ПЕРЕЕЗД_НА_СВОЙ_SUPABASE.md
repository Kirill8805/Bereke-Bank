# Переезд проекта Bereke AI на свой Supabase

Короткая инструкция: как поднять собственную базу и подключить к ней проект. Данные со старого проекта не переносим — таблицы будут пустые, схема та же.

## Что уже подготовлено в папке проекта

- `supabase/schema_full.sql` — весь SQL для создания таблиц, ролей и хранилища (собран из миграций).
- `.env.example` — шаблон переменных окружения со всеми нужными ключами.

## Шаг 1. Создать новый проект Supabase

1. Зайдите на [supabase.com](https://supabase.com), войдите (можно через Google/GitHub).
2. **New project** → задайте имя, придумайте и **сохраните пароль базы**, выберите регион (ближе к вам, например Frankfurt).
3. Дождитесь, пока проект поднимется (1–2 минуты).

## Шаг 2. Создать схему базы

1. В новом проекте откройте **SQL Editor** → **New query**.
2. Откройте файл `supabase/schema_full.sql`, скопируйте **всё** содержимое, вставьте в редактор.
3. Нажмите **Run**. Должно выполниться без ошибок.
4. Проверьте: в **Table Editor** появились таблицы `profiles`, `chat_sessions`, `chat_messages`, `app_settings`, `user_roles`; в **Storage** — бакет `avatars`.

## Шаг 3. Скопировать ключи и заполнить `.env`

В Supabase: **Project Settings → API**. Понадобятся:

| Что в панели | Куда в `.env` |
|---|---|
| Project URL | `VITE_SUPABASE_URL` и `SUPABASE_URL` |
| Project ID (из URL) | `VITE_SUPABASE_PROJECT_ID` |
| `anon` / publishable key | `VITE_SUPABASE_PUBLISHABLE_KEY` и `SUPABASE_PUBLISHABLE_KEY` |
| `service_role` (secret) | `SUPABASE_SERVICE_ROLE_KEY` |

Скопируйте `.env.example` в `.env` и подставьте значения. `service_role` — секретный, его нельзя показывать на клиенте и коммитить в git.

## Шаг 4. Настроить ИИ (иначе чат-тренажёры не отвечают)

Модель раньше вызывалась через шлюз Lovable (`LOVABLE_API_KEY`), при переезде он недоступен. Рабочий путь — свой ключ OpenAI:

1. Зарегистрируйтесь в приложении (Шаг 6) и станьте админом (Шаг 5).
2. В админ-панели приложения введите **ключ OpenAI** — он сохранится в таблице `app_settings`, и чаты пойдут через OpenAI (`gpt-4o-mini`).

Пока ключ не введён и `LOVABLE_API_KEY` пуст — тренажёры будут выдавать ошибку при отправке сообщения.

## Шаг 5. Сделать себя админом

Админ-роль выдаётся по записи в `user_roles`. Автоматический «посев» в схеме срабатывает только для email `1@gmail.com` и `4@gmail.com`, если такой пользователь уже зарегистрирован. Проще:

1. Сначала зарегистрируйтесь в приложении под своим email (Шаг 6).
2. Потом в **SQL Editor** выполните (подставьте свой email):

```sql
insert into public.user_roles (user_id, role)
select id, 'admin' from auth.users where email = 'ВАШ_EMAIL'
on conflict do nothing;
```

## Шаг 6. Запустить проект

```
bun install       # или npm install
bun run dev       # или npm run dev
```

Откройте адрес из терминала, зарегистрируйтесь, вернитесь к Шагу 5 (сделать админом) и Шагу 4 (ключ OpenAI).

## Частые проблемы

- **«Missing Supabase environment variable(s)»** — не заполнен `.env` или не перезапущен `dev`-сервер после правки `.env`.
- **С фронта не приходят данные, хотя в базе они есть** — это RLS: пользователь видит только свои строки. Для админских операций сервер ходит через `service_role`.
- **Чат отвечает ошибкой** — не задан ключ OpenAI в админке (см. Шаг 4).
- **Регистрация/письма** — в Supabase → Authentication можно отключить подтверждение email на время разработки (Providers → Email → Confirm email off).
